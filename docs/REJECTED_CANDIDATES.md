## 重开条件

以下任一前提成立时，上述候选值得重新评估，而不是直接沿用原结论：

1. **对照对象变了。** 原比值都是对特定父版（9ed、760f 或 311b45f 等）测的。父版被替换、
   或被否决项所在路径（typed 输出、批量写、索引构建、缓存构建）本身被重写后，原比值不再是
   该候选的证据，需要重新配对测量。
2. **样本量和顺序补齐。** 只有 2 对的专项（index batch A、payload batch B、disk no-init、
   raw copy 的 spill 专项）属于筛选级证据；补到 ≥6 对并带 A/A 同程序对照、交错 AB/BA 后
   才具备否决或采纳的资格。原决定在样本补足前保持不变。
3. **触发条件本身被放宽或被证明不适用于当前场景。** 例如默认 CPU1 稳定退步这条保护规则
   若被正式改写，或确认目标场景只跑宽输出/只跑 spill，则 typed wide、低维 BULK、raw copy
   的否决理由需要按新规则重算；不得先改门槛再宣布通过。
4. **前置阻断消失。** PGO-only 是 0 对性能的身份不一致阻断，lazy typed 是 0 对性能的资源失败
   阻断。修好 release 与独立构建的 ELF 一致性、修好第 17 次分配 32B 的 noexcept 析构抛出路径后，
   这两项才从「无结论」变成「可测量」，重开的是测量而不是结论。
5. **ISA 与主机条件明确。** AVX2 dot/norm 需要一台确认没有 AVX512、能实际进入目标 ISA 路径的
   主机，且强制关闭与强制开启两侧都用同一 ELF 对照；否则 micro 收益不可归因。
6. **编译链变化。** LTO 与扩大 PGO 训练的结论绑定当时的 g++/PGO 训练集；工具链版本、
   训练覆盖集或构建参数改变后需要重跑，不能沿用 0.988×。
7. **场景口径改变。** small compute 单 fan-out 的负收益集中在双 CPU 默认、宽输出和 spill q1；
   如果部署固定单 CPU，或 fan-out 启动策略被另一套调度成本结构替换，该策略可重新进入候选，
   但仍需完整 120 对，不能用 24 对同 ELF 对照代替。
