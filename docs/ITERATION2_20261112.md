## 整数点积候选

这是 assistant 从量化热路径提出的具体方案，不是用户报告中的原样算法。量化码限定在 [-127,127]，通过 AVX2 abs/sign/maddubs/madd 精确计算点积；每对乘积不会触及饱和，点积总和在 int32 内。平方范数预存为 uint32，最终用 int64 重建距离；65536 维最大距离可超过 INT32_MAX，测试独立使用 uint64 oracle。

独立微基准 15 对的中位加速比为 1.6898×，范围 1.6194–1.7647×；该值仅属于整数核，不能当作数据库提速。10k 行额外范数为 40000 字节，微基准构建约 0.112–0.117 ms。

集成实现按原预算剩余额度准入范数，不挤占同一索引既有 posting、量化码与 ANN 预留；预算或分配失败时沿用旧核。新增缓存会计入全局已用内存，可能影响后续其他表的准入。仅在原分派选中 AVX2 且维度至少 32 时启用；AVX512、低维和不支持的 CPU 保留原路径。

集成提交 `61a2b2f26e54894f20274c376e7f7a3474e360ff` 的完整门禁与 135 对测量正在进行；结果待补充。

## PGO 候选

方向来自用户报告 I15，训练器和验证方法由 assistant 实现。训练种子与评估种子独立，训练覆盖 16/128/512 维、K=1/10/100、过滤、更新、回滚和重启。dyadic 浮点输入允许独立 double 全排序 oracle 精确检查每个响应。训练与 profile 只用于构建，发布镜像只含最终程序与空数据目录。

保持固定 GCC 13.3、O3/static 和现有浮点语义，生成阶段使用 atomic profile；使用阶段要求所有翻译单元的反馈存在且匹配，不使用 profile-correction。当前为实验工具，尚未启用到默认 Dockerfile，结果待补充。
