# MiniVectorDB 第二轮实测记录

本轮继续从已保留的 `5a67f1690c46239cf4340ee40437bab5988c82ca` 迭代；整个分支的起点仍为用户指定的 `a90b2b750e40f020793cddefe01d5b66631afc63`。`5a67f16` 的运行源码与前轮 `4d8de37` 相同。用户报告是参考方向，报告和用户要求记为 `user`；算法选择、代码实现、测试与解释记为 `assistant`。不把代理测得的结果写成用户反馈。

正式目标仍为 6000，但目前没有本轮代码的正式评分。以下是固定编译器、同一 runner 的诊断实验，不能换算平台 E/M/B。前轮结果见 [第一轮记录](ITERATION_20261112.md)。

## 解析与残差界限：已测后回退

实验提交 `8dbd2063fb639619e91c08efe89a26911fa7049d`，基线为 `5a67f16`。用编译期开关分别测 parser-only、residual-only、组合版本，每种默认负载 15 对；组合版本再测七种边界各 15 对，共 150 对。三个评估种子各五对，交换启动顺序，保留全部样本。

- **I13 用户方向：减少解析复制。** assistant 实现借用 token、解码文本单独持有、AST 继续拥有值，并省去 INSERT VECTOR 路径的字符串保留。默认查询 1.0058×、生命周期 1.0045×，收益不足 1%，未保留该实现。前轮省去 `Statement.raw` 的改动保留。
- **I11 用户方向：改善量化。** assistant 实现表级最大量化残差与查询残差的保守上界。查询 1.0233×，但索引构建 0.8095×、生命周期 0.9976×，未保留。
- **组合：** 默认查询 1.0071×，构建 0.8271×，生命周期 0.9902×，三个 seed 的生命周期均回退。UPDATE 10 行后 64 次查询 37.402 ms → 42.045 ms；第一条的重建由 19.315 ms 增至 23.977 ms，不能从主要指标中删除。

比值是每对基线耗时/候选耗时的中位数，大于 1 为快。默认更新前与重启后各 1000 次查询；边界每阶段 64 次。所有 150 对响应摘要一致，抽样独立 oracle 与重启核验通过；进程 RSS 仅数十 KiB 差异，I/O 代理相同。低维过滤与短生命周期的回退也保留在 [机器结果](../validation/iteration2-results-20261112.json)。

完整门禁通过，SQL 默认/单线程/双线程各 10251 项，无失败；源码和镜像公开用例各 20/20，事务、恢复和已有 sanitizer 门禁通过。此提交尚未包含后来新增的直接 parser/quantized ASan 检查，不能倒填。残差实现的独立 Python Fraction 模型另测 800 对，新增 615 次安全拒绝，无错误，但安全拒绝更多并不等于总时间更少。

## 整数点积候选

这是 assistant 从量化热路径提出的具体方案，不是用户报告中的原样算法。量化码限定在 [-127,127]，通过 AVX2 abs/sign/maddubs/madd 精确计算点积；每对乘积不会触及饱和，点积总和在 int32 内。平方范数预存为 uint32，最终用 int64 重建距离；65536 维最大距离可超过 INT32_MAX，测试独立使用 uint64 oracle。

独立微基准 15 对的中位加速比为 1.6898×，范围 1.6194–1.7647×；该值仅属于整数核，不能当作数据库提速。10k 行额外范数为 40000 字节，微基准构建约 0.112–0.117 ms。

集成实现按原预算剩余额度准入范数，不挤占同一索引既有 posting、量化码与 ANN 预留；预算或分配失败时沿用旧核。新增缓存会计入全局已用内存，可能影响后续其他表的准入。仅在原分派选中 AVX2 且维度至少 32 时启用；AVX512、低维和不支持的 CPU 保留原路径。

集成提交 `61a2b2f26e54894f20274c376e7f7a3474e360ff` 的完整门禁与 135 对测量均完成。这里必须区分两个 runner：验证 job 的 EPYC 7763 仅支持 AVX2，确实覆盖新路径；性能 job 的 EPYC 9V74 支持 AVX512，按分派逻辑沿用旧核，没有分配范数。该路径判断基于 CPU flags 与明确的源码选择器，并非额外的运行时计数器。

AVX512 默认对照中，基线 → 候选查询 0.98755×、重启后查询 0.98337×、生命周期 0.98858×；同源码禁用 dot → dot 查询 0.98832×。三个 seed 的默认查询均略慢，未表现收益。该结果只反映 AVX512 保留路径与代码布局/分支开销，不能否定或证明 AVX2 内核的端到端效果。为补上这个缺口，后续两端统一禁用 AVX512 量化核，再做明确的 AVX2 对照。

正确性方面，新增 SQL ASan/UBSan 单/双线程各 10251 项通过，量化 2490 对及范数预算/分配失败测试通过；源码和镜像公开用例各 20/20，原有事务/恢复/故障门禁通过。未来检查再显式禁用 AVX512 量化核，以免 runner 更换后漏测可选 dot 路径；这不改变发布程序的 CPU 分派。

统一 AVX2 的补测在 `502931d` 完成，共 135 对，三方编译探针均确认选中 AVX2，只有 dot 版本具备新路径资格；浮点界限仍采用相同的本机分派，并非模拟整台 AVX2 CPU。相对 `5a67f16`，默认查询仅 1.00467×、生命周期 1.00114×；同源码禁用 dot 的消融对照查询为 1.02491×，说明点积实现本身有收益，但集成后的整体成本抵消了大部分收益。30k 查询 1.06087×，low16 查询 0.96652×；内存中位额外 45,056 字节（标准基线对照）和 126,976 字节（30k）。

**最终撤回本轮 dot 运行实现，恢复上一轮运行源码。** 原因是默认规模净收益接近噪声，同时低维与默认 AVX512 有回退。新内核及专属测试可在实验提交中复核，通用 SQL/INSERT 回归继续保留。不能把独立微核的 1.69×、同源码消融的 1.025×或 30k 的收益套到最终程序。

## PGO 候选

方向来自用户报告 I15，训练器和验证方法由 assistant 实现。训练种子与评估种子独立，训练覆盖 16/128/512 维、K=1/10/100、过滤、更新、回滚和重启。dyadic 浮点输入允许独立 double 全排序 oracle 精确检查每个响应。训练与 profile 只用于构建，发布镜像只含最终程序与空数据目录。

保持固定 GCC 13.3、O3/static 和现有浮点语义，生成阶段使用 atomic profile；使用阶段要求所有翻译单元的反馈存在且匹配，不使用 profile-correction。

首次提交 `1dd2da8` 的常规完整门禁成功，镜像程序与 `61a2b2f` 哈希相同；独立 PGO job 在训练工具编译处失败。原因是 helper `quoted` 与 `std::quoted` 经 ADL 冲突。修复仅将该函数及调用更名为 `sql_quote`，未改语料和断言。失败时尚未开始训练或性能配对，不能报告 PGO 收益；[失败记录](../validation/iteration2-pgo-build-failure.json)保留原始阶段和日志哈希。

修复后 `502931d` 的 PGO 隔离实验在 EPYC 7763、实际 AVX2 无 AVX512 的 runner 上完成。六次训练验证的三个阶段分别有 951/41/14 条响应；6/6 个反馈文件哈希匹配，严格反馈编译、发布镜像隔离与八项二进制门禁全部通过。三个独立评估种子各五对，标准每阶段 1000 次查询，六个边界每阶段 64 次，共 105 对全部响应一致。

| 同源 PGO 隔离场景 | 查询加速比 | 生命周期比 |
| --- | ---: | ---: |
| 默认 10k | 1.0577×（15/15 对更快） | 1.0493× |
| 30k | 0.9859× | 1.0304× |
| 50k | 1.0612× | 1.0220× |
| 低维 10k | 1.1743× | 1.0389× |

30k 与落盘查询在三个 seed 中均回退，结果未删除。进程 HWM 中位约少 0.19 MiB，`/proc` I/O 代理不变，不等同官方内存/设备 I/O 分数。以上对照两端均包含当时的 dot 运行源码；它只能说明那个源码上的 PGO 效果，不能与 dot 比值相乘推算最终组合。

最终候选采用**上一轮运行源码＋构建期 PGO**。根 Dockerfile 默认 `ENABLE_PGO=1`，仍可用 `--build-arg ENABLE_PGO=0` 做诊断对照。训练与最终程序的路径、编译器和选项保持一致；发布层仅复制 `/minivec` 和空 `/data`。最终同一镜像的完整门禁和直接对照 `5a67f16` 的 105 对测量待完成。
