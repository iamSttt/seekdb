# MiniVectorDB 本轮优化与实测

本轮严格从用户指定的 `a90b2b750e40f020793cddefe01d5b66631afc63` 开始。用户报告中的方向被筛选使用，报告原文和本轮要求以 `role: user` 保存在两份一致的 `conversation.json` 中；实现、测试、结果解释均归属 `assistant`。未导入旧聊天作为本轮学习证据。

**已证实的收益集中在驻留切换边界、少量 UPDATE 和磁盘索引构建。默认 10k 查询目前没有显著提速，6000 分尚未验证。** 当前正式平台最近一次可见记录为旧提交 `ee299adb296a2922d01982aa6c5707d37e767b41`，E=3014.419039，Prompt 原始分为空并提示无效/待复核等组合原因。它不是本轮候选的成绩，平台未给出 T/B/M 或准确的 Prompt 失败分支。

## 已采用的方向

| 用户报告 | 实际修改 | 边界 |
| --- | --- | --- |
| I03 驻留准入 | 按借用指针、PK、slot 与容器容量计算元数据，计入 posting、量化和构建峰值 | 原 16 MiB 索引预算不增加；保留原 65,536 行 posting 覆盖 |
| I04 少量 UPDATE | 1 MiB 全局 before-image 上限；少量修改保持表驻留；超限时先写所有活跃旧值再发布迁移 | 正确处理语句失败、回滚、多表和恢复；不是无限内存 Undo |
| I08 批量写入 | 磁盘 FlatIndex 使用 256 KiB 或单条超大记录的构建缓冲，末尾 flush，失败后禁止继续发布 | payload spill 的批量写入尚未实现 |
| I13 解析分配 | 执行入口跳过未使用的整条 SQL `Statement.raw` 复制 | 保留解析器默认 API 与错误语义；未重写 tokenizer |
| I15 LTO | 同编译器、同代码，单独试验 `-flto=2` | 实测没有可靠净收益，默认 Dockerfile 不启用 |
| I14 JSON 行编码 | 试验每 SELECT 复用行数组，并与代理提出的量化 cap 缓存改动组成候选 | 默认查询微增、多个边界退步，已回退这组运行改动 |
| I02 测量 | 成对交替顺序、三个种子、每种子五对，补录构建/首次查询/更新/关闭/重启 | 这些是诊断负载与进程代理，不能代替正式计分 |

## 已完成的性能实验

比值为每对的“基线耗时/候选耗时”再取中位数，大于 1 表示候选更快；不是两组中位数的比值。每个场景 15 对，保留所有慢样本。

### 首批三项运行修改

基线 `a90b2b7` 与 `30a44d5`：9 场景、135 对；后续 `ada4add` 仅修正测试前提，运行源码相同。10000–60000 行、16/128 维、K=10，短批次每阶段 32 次查询，包含独立等值过滤场景。全部响应摘要一致，抽样独立 oracle 通过。

| 场景 | 查询加速比 | 其他结果 |
| --- | ---: | --- |
| 35k × 128 | 1.681× | 索引构建 2.425×，生命周期 1.114× |
| 50k × 128 | 1.598× | 索引构建 2.396×，生命周期 1.104× |
| 10k 更新 1 行 | 更新后 1.606× | UPDATE 本身 11.42× |
| 10k 更新 10 行 | 更新后 1.651× | UPDATE 本身 10.80× |
| 10k 更新 100 行 | 更新后 1.616× | UPDATE 本身 8.99× |
| 50k 宽行落盘 | 见机器可读结果 | 索引构建 1.566×，生命周期 1.043× |
| 30k × 128 | 2.470× | 构建 0.164×，生命周期 **0.955×** |
| 10k × 16 / 60k 低维过滤 | 0.970× / 0.980× | 首轮查询略慢；生命周期 1.005× / 1.002×，重启后查询 1.014× / 0.997× |

表中查询为重启前阶段；UPDATE 场景则为修改后阶段，其第一条查询包含索引失效后的重建，不能直接理解为稳态 QPS。30k 生命周期包含重启前后各 32 次、共 64 次查询。重启时已登记索引在 `open()`、ready 之前重建，成本计入 restart 阶段。

30k 的负结果来自完整成本：预算修正允许分配约 3.84 MB 的量化码，构建中位时间由约 9.85 ms 增至 59.81 ms，32 次查询由约 46.63 ms 降到 18.55 ms；短批次的生命周期仍慢约 4.7%，进程最大 HWM 增约 13.4%。这项取舍保留在候选与证据中，不能只引用其查询提速。

### 默认规模与 LTO

基线 `a90b2b7` 对 `4d8de37`，10k 行、128 维、K=10、半数等值过滤，三个种子×五对；更新前与重启后各 1000 次查询。另对同一候选与只增加 LTO 的二进制做相同配对。

| 比较 | 查询 | 生命周期 | 结论 |
| --- | ---: | ---: | --- |
| 基线 → 候选 | 1.002× | 1.080× | 查询持平；生命周期范围 0.822–3.409×，写入噪声大，不认定稳定 8% 收益 |
| 候选 → LTO | 0.988× | 0.983× | 查询略慢，保持默认构建 |

以上全部响应摘要一致。候选进程峰值 HWM 相比基线约多 20 KiB；I/O 代理不变。该默认规模实验没有证据支持“查询翻倍”或“达到 6000”。

### 追加热路径候选：实测后回退

`991d105` 试验每 SELECT 复用 JSON 行数组，以及将量化拒绝阈值转换成等价的整数 cap 并缓存合法性检查。两处改动组合对照 `4d8de37`，没有分别归因其单独收益。完整门禁通过，另完成默认 1000 查询 15 对、五个边界场景每阶段 64 查询共 75 对，响应与抽样 oracle 全通过。

| 场景 | 查询成对中位加速比 | 生命周期比 |
| --- | ---: | ---: |
| 默认 10k | 1.0125× | 1.0033× |
| 30k | 见机器记录 | 0.9874× |
| 35k | 0.9774× | 见机器记录 |
| 50k | 0.9976× | 见机器记录 |
| 低维 10k | 1.0407× | 1.0070× |
| 过滤 60k | 见机器记录 | 0.9843× |

标准查询 p95 比值仅 1.0070×。收益不足以抵偿多个场景的退步，因此最终运行源码恢复到 `4d8de37`；回退的是这组微调，前面的 I03/I04/I08/I13 保留。新测试与真实负结果继续保存。

## 可重复运行

在 Linux、Docker、Git、Python3 可用的环境中，从完整 Git 历史检出本轮分支。脚本要求自己的输出目录不存在，以防覆盖旧证据。

```sh
bash minivec/tools/ci_score.sh
bash minivec/tools/ci_iteration.sh
bash minivec/tools/ci_standard.sh
python3 minivec/tools/validate_iteration_material.py
```

根 Dockerfile 固定 GCC 13.3.0、静态链接与 `-O3`。配对实验在同一 GitHub runner 上固定两 CPU affinity，交替启动先后次序；没有清理宿主页缓存，也没有对性能进程施加正式 cgroup 限制。构建、首次查询、最终 shutdown 和 restart 的耗时均单列。随机数据生成和 oracle 计算在计时外。

## 证据限制与后续

- `/proc` RSS/HWM 和进程 I/O 是诊断代理，未覆盖 page cache、整个 cgroup 和 shutdown 后的所有资源开销，不能替代官方 M/B。
- 三种 seed 的 Gaussian 数据与抽样独立 `math.fsum` oracle 不能代表隐藏数据分布；独立数值边界测试用于补充，公开门禁仍不等于隐藏准入。
- ASan 未启用 leak detection；故障注入覆盖短写/失败写，未穷尽 fdatasync、内存分配失败等所有错误。
- 用户报告属于真实提供的输入；本轮代理测量不能当作用户亲自实验、反思或独立技术发言。JSON 机械校验通过不能证明官方 Prompt 评分有效。
- [当前赛题](https://oceanbase.yuque.com/org-wiki-obtech-vh7w9r/hc3pio/lg8enxlmwg69unt6) 的有界性能公式与平台显示数千分之间没有已验证的尺度映射。没有把本地加速比乘以 3014，也未发起新的正式提测。
- 后续正式验证应锁定最终提交、默认 `agent/conversation.json` 和摘要，取得分项后再决定主要投入。默认静态 10k 数据与本轮大表/UPDATE 的受益条件不同。
