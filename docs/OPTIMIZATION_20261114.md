## 基线与交接结论

从 `a90b2b750e40f020793cddefe01d5b66631afc63` 清理版开始：其构建和运行代码与最高分 `ee299adb296a2922d01982aa6c5707d37e767b41` 等价。本轮重新从 EE 的原始根 Docker 上下文构建配对基线；这个重建程序不是平台实际 ELF。

没有沿用交接实验分支 HEAD，因为其中仍有已否决的 quarter 距离候选。也没有打包移植保留 R 的所有优化：其 spill/wide 专项收益不能替代默认查询、重启和内存保护。交接记录中已否决的提前退出、CRC、线程策略、全量 typed JSON 和 batch8 等，本轮不重复加入。

## 本轮候选

1. **请求预处理**：对已经完整验证的常见 ASCII execute 请求，直接保留 SQL、原始 ID 字节及 search mode，省去临时 JSON DOM 和 ID 重扫。嵌套、转义、非 ASCII、未知字段及不适用的操作回退到原严格 JSON 解析。必须保持全部输入验证先于执行、重复键错误、巨大 ID、UTF-8、shutdown 和事务语义。
2. **128 维整数距离**：在查询初始化时选择固定长度 SSE2/AVX2/AVX512 核，用独立部分和减小累加依赖；不改量化编码、浮点距离、拒绝证书、候选选择和非 128 维路径。128 个 int8 差值平方和最大为 8,323,200。仍有原来的每行函数指针调用，不能声称消除了 dispatch。

根 Docker 编译器、构建参数和线程策略保持不变，没有新增 PGO。两项均是尚待实测的假设，不预报官方分数。

## 验证与采用标准

先运行实际根镜像、公开 20 用例、交互协议、JSON/精确 TopK、恢复和 sanitizer 回归，再跑两项新增差分检查。固定长度测试另核对所有支持 ISA、独立整数 oracle、边界页、非 128 维和完整拒绝判断。请求测试用旧新镜像二进制检查 464 条输入：其中两条原始 NUL 的拒绝是明确的修复差异，其余保持逐字节响应等价；另有四条 NUL 尾部写入/删除/shutdown 的无副作用和重启检查。

性能初筛使用相同主机、EE 原始根构建、10k 行/128 维/1000 exact 查询；1 CPU 和 2 CPU 各六对，AB/BA 交错，2 GiB、swap=0，固定种子 7319。保留所有样本及重启、首查、内存和 I/O 数据，不按结果删除慢样本。首生命周期 wall/CPU 至少改善 5%、查询 wall/CPU 至少改善 10%，各主指标至少五对更快且两种顺序各自中位数改善，才继续完整保护和独立确认。

这只是 EE 的 12 对初筛，不是交接记录中的完整 24 对验收，也不是正式性能评测。阈值和范围已在运行前写入 `validation/from-best-plan-20261114.json`。未通过初筛时，不建议替换当前 3014 分版本。

下一独立原型是有证明区间的延迟精算 TopK，仅拟用于显式 exact、128 维、无过滤、升序、已有 resident fanout 且 K≤32 的路径。每个距离区间必须覆盖规范的精确结果；严格不相交时直接比较，否则用整数 ExactSum 和原 PK 顺序判断，最终幸存者全部物化。它可能减少中途被淘汰候选的精算，但密集等距数据仍可能几乎每行走更贵的整数精算。原型和数学复审不等于实现正确性或收益已验证，未实测前不作为可提交优化推荐。
