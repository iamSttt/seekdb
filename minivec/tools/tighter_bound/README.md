# Tighter long-double fallback candidate — prepared, not executed

Only the candidate header is a proposed production change. The original four-lane scalar summation, original error formula, and first strict certificate are untouched. After an old certificate fails, a guarded second certificate uses `old_error*0.5L`. The guarded x87 PC64/RN error proof is in `../tighter-longdouble-bound-review.md`; its independent review found no blocker. Halving the original normal error is exact and equals the proven epsilon coefficient. No FMA, new arithmetic reduction or fitted constant is introduced.

`reference_distance.h` is exported as raw Git bytes, not from the CRLF Windows worktree: SHA256 `7094c0892de1b56377a65675a119a942cd07959f22e128673738c6c953fc1fe9`; the commit/path and candidate SHA are in `source-proof.json`. `candidate.patch` records the complete runtime difference. The guard restricts x86_64/radix2/64-bit-size_t/x87 extended format and tests PC64/RN, exception masks and MXCSR RN/noDAZ/noFTZ without clearing sticky status. Every unsupported case keeps the old path. That is compatibility, not a claim that legacy PC24/PC53/non-RN behavior is correctly rounded.

No file in the production repository is modified by this package. Preparation and Python structural checks are not native correctness or performance results.

The mathematical proof and this package's source/harness received independent static review without a blocking finding. The runner distinguishes attempted native compilations/executions from successfully completed ones, so an unsupported or failing native attempt cannot be reported as zero attempts. No native run has occurred during preparation.

## Fixed future execution

Run `python3 run_linux.py --output /absolute/new/output/directory` on Linux x86_64 with GCC **13.3.0**. The output directory must be outside this immutable package and not already exist. The intended toolchain image is `gcc:13.3.0-bookworm@sha256:1d71f0f3450214bef38fe09e6f610fb6cca90cf97b43f4ce845bfc32a4168818`; the caller owns launching the fixed container/toolchain. The script records compiler, actual commands, affinity and readable resource files, and pins itself and children to one allowed CPU. It records resource settings as observations; it does not claim a 2 GiB cap or swap policy unless the caller actually provides them. There is no PGO, database or formal evaluation.

The fixed run performs four native builds:

1. Normal `-O3` correctness and `-O1` ASan/UBSan correctness. Independent Python arbitrary-precision integer squares and Fraction single rounding provide expected binary64 bits, separate from C++ `distance_exact`. Both original scalar and candidate are checked. Fixtures cover all finite exponent classes, signed zero/subnormals/extremes, opposite/near/widely separated coordinates, exact ties and their neighbors, all tails and dimensions through 262144. Ten analytically chosen fixtures exercise the smaller interval; they are never timed. Native markers: `tighter_bound=PASS`, `tighter_bound_checks=N`.
2. A separate **counter-only shadow** counts `old_cert`, `tight_rescue`, and `integer`; all calls must be conserved and original successful certificates must remain successful. It checks the three micro corpora plus an analytic rescue. This instrumented binary is never timed.
3. An uninstrumented micro binary compares old/candidate wrappers from one compilation. Fixed corpora: `fullmantissa128`, `fullmantissa512`, `grid128`; 512 independent vector pairs each; 64 repetitions per timed arm. The full-mantissa corpus uses independently seeded signed binary32 values with raw exponents 124–128. The grid control uses exact multiples of 1/4096, whose distances certify on the old path. These are generic kernel corpora, not copies of competition requests or data. Each scenario gets exactly four pairs, AB/BA/AB/BA; scenarios rotate between pair indices. Wall and thread CPU, faults, context switches, checksums, data fingerprints and every negative pair are retained.

The timing loops include the entire scalar distance call, extra guard/rescue cost and a common result checksum. No counter or per-call timer is inserted. The runner does not choose a winner or alter any constant based on results. Four synthetic pairs only screen a mechanism; actual-root paired tests against the retained and highest references would still be needed before adoption. These results cannot guarantee an official score.
