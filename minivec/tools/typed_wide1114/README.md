# Typed-wide single-factor experiment

Runtime is `9595e1477af1325795b0f9fed52e6a44bb217b1c`, a two-file production change on `760f66220f2c7186b4ba295f9e3065650e549f9e`. The later driver commit has identical root runtime inputs. Root Docker remains unchanged and uses no PGO. This is an isolated factor measurement, not an EE/R release gate or official score prediction.

The runtime enables R33's typed writer only for JSON SELECT projections containing at least one non-distance VECTOR of dimension >=128. Other rows keep DOM encoding. Header bytes come from R33; only the two existing row-output points are changed in exec.cpp. Stable string ownership, strict UTF-8, pinned float formatting, int64 values, canonical distance, PK ties and error atomicity are preserved. Ordinary scalar queries still incur the guard and changed code layout, but hold only an empty owning pointer. Zero overhead is not assumed.

The native run first executes the inherited full root correctness/protocol/recovery/numeric/sanitizer checks and the existing integer-cap and spill-cache guards. The source-factor adapter then adds writer byte oracles and 54 executor UTF8 cases under pinned O3 and host ASan/UBSan, 54 live UTF8 cases for each actual root ELF, paired complete output bytes plus independent values/order at 16/127/128/129/768 dimensions, request/numeric differentials and the independent shared-bound oracle. The SQL subset permits one vector column per table, so ordinary and extreme float32 fixtures use separate tables. NULL is rejected rather than treated as a supported stored type. There is no internal typed-path counter.

Frozen source-factor schedule uses unchanged original measurement vendor and pure guard readers: default CPU1 and CPU2 each4 pairs, spill_high_q16 CPU1 two pairs, wide768 CPU2 two pairs. AB/BA order and all31 original metric summaries are retained. Both wide pairs must individually have candidate/760f <=0.90 for seven-phase query wall and CPU, and <=0.95 for the lifecycle-stage wall sum. Original time2% and memory5% stable protection remains applied to all31 metrics, including default/spill; all negatives remain in the raw report. No new trial may be chosen selectively to make a failure pass.

Source and actual root ELF are separately bound. Fresh parent root build must reproduce `fbeeb83977779eae977f5bec4f570b68ed7bfd5c87bb6642b7e5ffeafa76d456`. Candidate SHA is verified from the separate assembly stage when available, otherwise initially unknown: verify_root checks its complete frozen runtime input inventory and records the ELF actually extracted from the root image, then run_ablation requires that same ELF/proof. Candidate source commit, driver HEAD runtime and frozen input bytes must agree. The unchanged workflow blob is also checked.

Raw output is `protocol-results/typed-wide/ablation.json` and its `.d` directory. Ordinary CI report dumping returns JSON and text through the existing workflow logs, including all pairs and subprocess failures. A regression completes and preserves reports but exits20; missing/failed input exits nonzero and never passes. Every report keeps `release_gate_passed=false`; this stage does not claim to resolve unrelated retained-R batch/PGO regressions. Full EE/R and later seed19087 confirmation remain required for future combined adoption.

Historical rationale: same-source typed-only PGO had wide768 top10/large/all about1.34/1.30/1.29x, but small-vector/update/spill negatives also existed. Later guarded results compared each candidate with a historical baseline, not directly guard versus spill. These old measurements cannot establish this port's speed or a score.

This last bounded variant adds only lazy owned state to the typed runtime: the string and writer are created upon the first actual wide row and retained together at a stable heap address for the query. No noinline annotation is included; actual prior compilation showed that formatter already outlined and no size/frame benefit from the annotation. The old typed performance result remains rejected and is not rerun. New actual assembly evidence must be reviewed before this last performance measurement. The additional OOM sweep uses no production hooks and does not assert a direct path counter.
