Implementation
==============
The old snapshot stored host FP32 vectors AND a complete cuVS snapshot containing
the same dataset. Header flag1 now omits the duplicate host vectors. On load,
the fixed-library cuvsCagraIndexGetDataset view restores the exact FP32 buffer
needed by CPU fallback and updates. Dimensions, dtype, strides and output size
are validated; row padding is supported. Copy failure aborts loading and frees
the handle. Historical flag0 snapshots remain readable. Old binaries reject
flag1; downgrading requires an old snapshot or index rebuild.

Temporary staging uses Linux memfd with close-on-exec instead of an intermediate
disk file. The final snapshot still uses seekdb's normal durable stream. If
memfd is unavailable/denied, tmpfile is used. Staging descriptors are closed on
all exits. Nothing is retained as a graph cache across independent builds.
Stage timings are logged at snapshot construction, outside the query hot path.

250K-vector payload sizes (header + external IDs + complete cuVS snapshot):
  256D: 610001745 -> 354001745 bytes (256000000 fewer bytes).
  128D: 354001745 -> 226001745 bytes (128000000 fewer bytes).

Construction/search settings are unchanged from official gate-passing v2:
NN_DESCENT, graph96/intermediate96/niter5; AUTO, itopk>=max(4096,4*topk), width1.
v3's persistent query worker remains. Fixed hipVS is unmodified. No new runtime
dependencies, phase detection, hidden-data routing or query-result cache.
